Notable changes in this release:

- Event data in a report is now read with the same converter that writes it ([#766](https://github.com/OpenVoxProject/openvox/pull/766)), so a deserialized event holds plain data only.
  Before this change, OpenVox Server rebuilt rich values from the event data in a submitted report, and a report whose event carried a crafted `__ptype` value ran code on the server as the `puppet` user.
  A client certificate was enough to submit such a report, which on a server that autosigns means any host that can reach it.
  See [GHSA-ffr6-rwpm-p5wq](https://github.com/OpenVoxProject/openvox/security/advisories/GHSA-ffr6-rwpm-p5wq), rated 9.4 critical; the same issue in Puppet Enterprise is CVE-2026-115731.
- The issue is reached through the server's report endpoint, which runs the agent's Ruby code inside OpenVox Server, so upgrade primary servers and compilers first.
  [OpenVox Server 8.18.0](/openvox-server/8.x/release_notes.html#openvox-server-8180) requires this release of the agent and restarts the service when it is installed; if you upgrade only the `openvox-agent` package on a server, restart `puppetserver` yourself.
  Agent-only hosts are not exposed by the issue and can upgrade on their usual schedule.
- A rich-typed value written by a Puppet 5 agent is no longer rebuilt into an object; its tagged hash arrives with the reserved keys renamed instead.
- This release is one of a coordinated set with OpenVox Server and OpenVoxDB. The [Vox Pupuli announcement](https://voxpupuli.org/blog/2026/11/03/critical-cve-updates/) lists every affected version and the mitigations available to a server that cannot upgrade yet.
