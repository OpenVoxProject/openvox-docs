Notable changes in this release:

- A `package` resource that uses the `gem` provider with `ensure => latest` and `--clear-sources` in `install_options` now checks for the latest version only in its `source` ([#798](https://github.com/OpenVoxProject/openvox/pull/798)).
  Before, the check also asked rubygems.org, so the resource reported a change on every run when rubygems.org had a newer version than the mirror.
- `Puppet::Type.clear_misses` removes the cached "type not found" results again, under the type registry's lock, and module loader lookups take the environment's lock ([#799](https://github.com/OpenVoxProject/openvox/pull/799)).
  Both matter on OpenVox Server, which runs this code. A type that was looked up before it existed stayed not found until a restart, and with `multithreaded: true` concurrent compiles could fail with `Attempt to redefine loader named '<module> private'`.
  Restart `puppetserver` after you upgrade the `openvox-agent` package on a server.
- The bundled OpenFact goes from 5.7.2 to 5.7.4:
  - Core facts find commands such as `ifconfig`, `route`, and `zpool` in `/sbin` and `/usr/sbin` again when `PATH` lacks those directories, as it does by default for non-root users on Debian and openSUSE ([openfact#237](https://github.com/OpenVoxProject/openfact/pull/237)).
  - A fact group's cache file is kept when a requested fact is missing from it ([openfact#252](https://github.com/OpenVoxProject/openfact/pull/252)).
    On a host where a fact in a cached group resolves to nil, the file was deleted and written again on every run with the old values, which then never expired as long as facter ran more often than the TTL.
- The FIPS packages get OpenSSL's FIPS provider from the same build as the bundled OpenSSL library, at the same version, 3.0.22 ([puppet-runtime#280](https://github.com/OpenVoxProject/puppet-runtime/pull/280)).
  It used to come from a separate build whose version was pinned apart from the library and fell behind it.
  The provider now gets the library's security fixes, and it is no longer held at a version that has a FIPS 140 certificate. See [Running OpenVox in FIPS mode](fips.html).
