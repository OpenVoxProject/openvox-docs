Notable changes in this release:

- The `openvox-server` package now requires `openvox-agent` 8.32.0 or later ([#766](https://github.com/OpenVoxProject/openvox-server/pull/766)), so upgrading the server also upgrades the agent on the same host and restarts the service.
  OpenVox Server runs the agent's Ruby code to process reports, and [OpenVox 8.32.0](/openvox/8.x/release_notes.html#openvox-8320) fixes [GHSA-ffr6-rwpm-p5wq](https://github.com/OpenVoxProject/openvox/security/advisories/GHSA-ffr6-rwpm-p5wq) in that code: a report with crafted event data ran code on the server as the `puppet` user, and a client certificate was enough to submit one.
- trapperkeeper-authorization is updated to 2.5.0, which fixes [GHSA-q4hm-33rc-572g](https://github.com/OpenVoxProject/trapperkeeper-authorization/security/advisories/GHSA-q4hm-33rc-572g), rated 9.5 critical; the same issue in Puppet Enterprise is CVE-2026-115732.
  The certificate name check in `auth.conf` rules compared only as many name parts as the shorter name had, so a certificate for `evil.node.example.com` satisfied a rule for `node.example.com`.
  On a server that autosigns, an attacker could request a certificate under such a name, then fetch another node's catalog or submit facts and a report in its name.
  After the upgrade, check any custom rules in `auth.conf`: a rule that relied on the old partial match now rejects names it used to accept.
- This release is one of a coordinated set with OpenVox and OpenVoxDB. The [Vox Pupuli announcement](https://voxpupuli.org/blog/2026/11/03/critical-cve-updates/) lists every affected version and the mitigations available to a server that cannot upgrade yet.
