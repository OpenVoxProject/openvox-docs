Notable changes in this release:

- trapperkeeper-authorization is updated to 2.5.0, which fixes [GHSA-q4hm-33rc-572g](https://github.com/OpenVoxProject/trapperkeeper-authorization/security/advisories/GHSA-q4hm-33rc-572g), rated 9.5 critical; the same issue in Puppet Enterprise is CVE-2026-115732.
  The certificate name check in `auth.conf` rules compared only as many name parts as the shorter name had, so a certificate for `evil.node.example.com` satisfied a rule for `node.example.com`.
  OpenVoxDB uses the same rules for the certificates allowed to reach its HTTPS endpoints, so a certificate issued under a longer name passed as a shorter one.
  After the upgrade, check any custom certificate rules: a rule that relied on the old partial match now rejects names it used to accept.
- The `openvoxdb` package now requires `openvox-agent` 8.32.0 or later ([#643](https://github.com/OpenVoxProject/openvoxdb/pull/643)), which brings the fix for [GHSA-ffr6-rwpm-p5wq](https://github.com/OpenVoxProject/openvox/security/advisories/GHSA-ffr6-rwpm-p5wq) to the database host; see [OpenVox 8.32.0](/openvox/8.x/release_notes.html#openvox-8320).
- If you run OpenVoxDB from the `container-openvoxdb` image, pull tag 8.18.0 or later. The image has also carried the fix for [GHSA-c4wc-g5pp-7wfp](https://github.com/OpenVoxProject/container-openvoxdb/security/advisories/GHSA-c4wc-g5pp-7wfp) since 8.17.0, rated 9.9 critical: the allowlist built from `OPENVOXDB_CERTIFICATE_ALLOWLIST` was never written, so any request reached the API.
- This release is one of a coordinated set with OpenVox and OpenVox Server. The [Vox Pupuli announcement](https://voxpupuli.org/blog/2026/11/03/critical-cve-updates/) lists every affected version and the mitigations available to a server that cannot upgrade yet.
